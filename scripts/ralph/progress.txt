2. **React Hook Ordering Violations** (`app/frontend/src/routes/combat/$combatId.tsx`)
   - Multiple state variables were used in useEffect dependency arrays before being declared
   - Violated React's rules of hooks, causing "Cannot access 'X' before initialization" errors
   - Variables affected: `showForfeitModal`, `showMissionCompleteModal`, `showVictoryCelebration`, `showPauseMenu`, `turnActive`, `economy`, `actionError`, `aiReasoning`, `showReasoningPanel`, `showOverchargeConfirm`, `contextMenu`

   - `test_apply_full_tech_miss_no_conditions` tested invade miss without forcing dice roll
   - Natural 20 always hits in Lancer regardless of defense, causing ~5% random failures
   - Fix: Added `settings=ResolutionSettings(forced_roll=5)` to guarantee miss

### Learnings

- **Hook ordering is critical**: When adding state variables to useEffect dependencies, ensure the useState calls appear BEFORE the useEffect in the component. This is documented in CLAUDE.md but easy to violate when multiple developers (or AI agents) add code to different parts of the same component.

- **Export completeness**: When creating new hooks in module files, always add them to the index.ts barrel export immediately. Missing exports cause runtime errors that tests don't catch.

- **Deterministic tests**: Per CLAUDE.md, always use `ResolutionSettings(forced_roll=N)` when testing specific hit/miss scenarios. The Lancer critical hit rule (nat 20 always hits) makes unforced tests flaky.

- **Test the app manually**: Running `make test` passes doesn't guarantee the app works. Hook ordering violations and missing exports are runtime errors that require actually loading the page to catch.
